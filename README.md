# yyj-writing-skills

> Claude의 주절주절 버릇을 잡아주는 문서 작성용 Claude Code 스킬 모음.

- Claude는 한국어 문서를 쓸 때 줄글로 길게 풀고, 막연한 형용사를 쓰고, 출처 없이 수치를 단정하는 버릇이 있다.
- 이 repo의 스킬은 그 버릇을 슬래시 명령 한 번으로 점검하고 고쳐준다.
- 대상은 한국어 가공 산출 문서: PRD(제품 요구사항 정의서), 리서치, 회의록, 요약 등.

## 수록 스킬

| 스킬 | 호출 | 하는 일 |
|---|---|---|
| `yyj-doccheck` | `/yyj-doccheck [파일경로] [--fix]` | 아래 24개 규칙 위반을 점검하고 수정안을 제시. `--fix`를 붙이면 본문에 바로 반영 |

스킬에는 검사 규칙 외에 "글쓰기 원칙" 섹션이 함께 들어 있다. 언어 앵커링(100% 한국어 문어체), 제안서체(명사형 종결), 라벨 콜론 형식, 자체 코드 ID 금지, verbatim 원칙, humanize 계열 윤문 스킬 적용 범위, 그리고 좋은 문장과 나쁜 문장의 퓨샷 예문까지. 검사는 사후 안전망이고, 문서는 처음부터 이 원칙대로 쓴다.

## 점검하는 규칙 24가지

> 표 읽는 법: 이런 문장을 쓰면(위반 예) 이렇게 바꾼다(수정 예).

| # | 규칙 | 위반 예 | 수정 예 |
|---|---|---|---|
| 1 | 막연한 형용사·부사 금지 | 데이터가 풍부하다 | 공개 출처 4종 + 실거래가 API, 2024 기준 |
| 2 | 출처 없는 수치 금지 | 80% 파악 | 80% 파악 (자체 추정, 검증 전, `가정:` 라벨) |
| 3 | 단정어 금지 | 당연히 수요가 있다 | 수요 추정. 근거: ... / 한계: 표본 5명 |
| 4 | 확증편향 점검 | 결론에 유리한 근거만 나열 | 반대 증거 1개 이상 + `데이터:`/`판단:`/`가정:` 라벨 구분 |
| 5 | 에세이형·질문형 제목 금지 | 이 문서가 답하려는 질문 | 개요 (명사구로) |
| 6 | 용어집 섹션 금지 | 문서 끝에 용어 정리 모음 | 첫 등장 자리에 괄호 설명: 라이선스(정부 허가, 자본금·심사 동반) |
| 7 | 풀어쓰지 않은 약어 금지 | MVP부터 만든다 | MVP(최소 기능 제품)부터 만든다 |
| 8 | 줄글 단락 금지 | A다. 그리고 B다. 따라서 C다. | `- A` `- B` `- C` 로 분해 + 결론에 요약표 |
| 9 | 줄표(—) 남용 금지 | 데이터 확보 — API로 받는다 | 데이터 확보: API로 받는다 |
| 10 | 가운뎃점(·) 남용 금지 | 아파트·상업용 중 택1 | 아파트/상업용 중 택1 |
| 11 | 마크다운 별표 금지 | `**핵심 결론**` | 제목으로 올리거나 핵심: 라벨로 |
| 12 | 따옴표 남용 금지 | 이른바 "가능성"이 보인다 | 가능성이 보인다 |
| 13 | 군더더기·미사여구 삭제 | 기본적으로 다양한 데이터를 효과적으로 활용 | 데이터를 활용한다 |
| 14 | 표로 바꿀 나열 | 기능마다 난이도+우선순위를 글머리로 나열 | 비교 축 2개 이상이면 표로 |
| 15 | 풀어쓰지 않은 압축 라벨 | (데이터: 발언, 미검증 → 변호사 확인) | 이 수치는 회의 발언이며, 사실 여부는 변호사 확인이 필요하다 |
| 16 | 남탓·대립 표현 금지 | 의견이 충돌해 합의 못 함 | 관점이 나뉘어 다음에 결정 (중립으로) |
| 17 | 이유 누락·브리핑 혼동 | 거짓 입력은 본인 손해다 | 거짓 입력하면 안 맞는 추천을 받아 본인이 손해다 |
| 18 | docx 표 물리 서식 | 라벨 열이 넓고 셀이 답답한 표 | 고정 레이아웃 + 라벨 열 좁힘 + 셀 여백 + 세로 가운데 |
| 19 | AI 입장·내부 표현 노출 금지 | 어디에 저장: `research/x.md` (이 저장소 안 새 파일) | 경쟁 분석 결과 (별도 문서로 정리), 경로는 문서 밖에서 안내 |
| 20 | 일기체·푸념·날조 금지 | 인터뷰 10명 진행 중 (실제 미시작) | 인터뷰 10명 예정(아직 미시작). 푸념은 빼되 진짜 이유는 남김 |
| 21 | 사용자 제약 무시 금지 | (예산 0인데) 경쟁 서비스 직접 구독해 분석 | 공개 자료로 분석. 유료가 필요하면 비용 먼저 확인 |
| 22 | 번역투·AI 상투구 금지 | ~에 있어서 시사하는 바가 크다 | ~에서 (직역 전치사 교체), 상투 결론은 액션 아이템으로 대체 |
| 23 | 서술체 종결 금지 (제안서체) | 채택 방식: 근거를 글에서만 가져온다. | 창작자가 실제 쓴 글에서 근거 수집 (명사형 종결) |
| 24 | 자체 코드 ID 금지 | 가설 K1, X1이 참이면 | 가설 이름으로 부름: 시리즈 일관성 붕괴가 참이면 |

- 규칙 1·2·3·5·6·7·9·10·11·12·15·16·19·22·23·24는 `grep`으로 자동 탐지한다.
- 규칙 4·8·13·14·17·18·21은 자동 탐지가 안 되므로 본문을 읽고 판단한다. 규칙 20은 `grep` 일부 + 본문 판단을 함께 쓴다.
- 규칙 14 표 기준: 비교 축(속성) 2개 이상이면 표, 1개면 글머리기호, 이어지는 설명은 줄글.
- 규칙 18 적용 시점: 줄글이 아니라 python-docx로 워드 표를 만들 때.
- 규칙 19·20·21은 문서를 읽는 사람(작성자·협업자) 입장으로 쓰기 위한 것이다. AI의 작업 절차·내부 경로·진행 푸념을 본문에 넣지 않는다.
- 규칙 22·23·24는 클로드 한국어 글쓰기 향상법 조사(번역투 원인 분석)와 사용자 직접 수정 예문을 기반으로 추가했다.
- 검사 안 함: 비정제 원본(대화 메모, 인터뷰 raw)과 발화 인용문. 원형 보존이 목적이라 규칙 미적용.

## 설치

- Claude Code는 `~/.claude/skills/` 안의 스킬을 자동 인식한다.
- 이 repo를 clone한 뒤 스킬을 그쪽으로 심볼릭 링크하면 끝.

```bash
# 1. 원하는 위치에 clone
git clone https://github.com/jiyuyeon/yyj-writing-skills.git ~/yyj-writing-skills

# 2. 스킬을 ~/.claude/skills 로 링크
ln -s ~/yyj-writing-skills/skills/yyj-doccheck ~/.claude/skills/yyj-doccheck

# 3. Claude Code 재시작 → /yyj-doccheck 사용 가능
```

- 링크 방식: `git pull`로 받은 업데이트가 즉시 반영된다.
- 복사 방식: 링크가 번거로우면 폴더째 복사한다. 단 업데이트마다 다시 복사해야 한다.

```bash
cp -R ~/yyj-writing-skills/skills/yyj-doccheck ~/.claude/skills/yyj-doccheck
```

## 업데이트

```bash
cd ~/yyj-writing-skills && git pull
```

- 링크로 설치했다면 그걸로 끝.
- 복사로 설치했다면 위 `cp` 명령을 다시 실행한다.

## 새 스킬 추가

- `skills/<스킬이름>/SKILL.md` 형식으로 폴더를 추가한다.
- 폴더명과 `SKILL.md`의 `name:` 필드가 일치해야 인식된다.

```
skills/
  yyj-doccheck/
    SKILL.md
  yyj-<다음스킬>/
    SKILL.md
```
