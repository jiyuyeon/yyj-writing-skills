# 문서 작성 규칙 셀프 검사

가공 산출 문서를 저장하기 직전(또는 이미 저장된 문서를 점검할 때) 작성 규칙 위반을 grep으로 잡아내고, 위반마다 **고치는 법**까지 제시한다.

## 적용 대상

- **검사함**: PRD, AC, Policy, 인터뷰 질문지, 페르소나, HMW, 가설표, 리서치, 요약, 회의록 등 **가공 산출물**
- **검사 안 함**: 비정제 원본(대화 메모, SNS 스크랩, 인터뷰 raw). 원형 보존이 목적이므로 규칙 미적용
- **예외**: 규칙·금지어를 *정의하는* 문장 자체에 금지어가 등장하는 것은 허용 (예: 이 SKILL.md, WRITING_RULES.md, agent 정의 본문)

## 검사 대상 결정

1. 인자로 파일 경로가 주어지면 → 그 파일을 검사
2. 인자가 없으면 → 직전 턴에 작성·수정한 문서 본문을 검사
3. 둘 다 불명확하면 → 사용자에게 "어느 파일을 검사할까요?" 한 번 묻는다

## 검사 절차

대상 본문에 대해 아래 grep을 순서대로 실행한다. 한국어 매칭이므로 `grep -nE` 사용. 파일이면 파일 경로를, 본문이면 임시 검사한다.

### 1. 막연한 형용사·부사

```
grep -nE '풍부|크게|너무|매우|충분히|쉽게|간단히|상당히|적절히' <파일>
```

- 매칭 시: 수치·예시로 교체하거나, 근거가 같은 문단에 있는지 확인. (Show, Don't Tell)
- 예: "데이터가 풍부하다" → "공개 출처 4종 + 실거래가 API — 2024 기준"

### 2. 출처 없는 수치·비율

```
grep -nE '[0-9]+%|[0-9]+배|[0-9]{2,}만|[0-9]{2,}억' <파일>
```

- 매칭마다: 단위·기준일·출처가 **같은 줄**에 있는가 확인. 없으면 추가.
- 예: "80% 파악" → "80% 파악 (자체 추정 — 검증 전, `가정:` 라벨)"

### 3. 단정어

```
grep -nE '당연히|명백히|확실히|반드시' <파일>
```

- 매칭 시: 근거가 같은 단락에 있는가? 출처가 1개뿐이면 단정형 금지.

### 4. 확증편향

- 자동 grep으로 안 잡힘 → **본문을 읽고** 판단:
  - 결론에 반대되는 증거를 최소 1개 적었는가?
  - 도메인 전문가 의견과 데이터를 같은 선상에 두지 않고 `데이터:` / `판단:` / `가정:` 라벨로 구분했는가?

### 5. 에세이형·질문형 제목 (명사구로)

```
grep -nE '이 문서가|할 것인가|왜 .*인가|어떤 .*있나|어떻게 .*나' <파일>
```

- 매칭 시: 명사구로 교체.
- 예: "이 문서가 답하려는 질문" → "개요" / "어떻게 받을 것인가" → "데이터 확보 방법"

### 6. 용어집 섹션 금지

```
grep -nE '^## 용어|용어집|용어 정리' <파일>
```

- 매칭 시: 용어집 섹션을 없애고, 약어·전문어를 **처음 나오는 자리에 괄호로** 설명.
- 예: "정부 허가(이하 라이선스 — 받아야 하는 허가·등록, 자본금·심사가 따름)"

### 7. 풀어쓰지 않은 약어 (이 문서만 봐도 이해되게)

```
grep -nE '\bD[0-9]\b|MVP|불요|CPA|딥링크|후크|트리거|API|노선[AB]' <파일>
```

- 매칭 시: 첫 등장에 괄호 설명 추가, 또는 우리말로 풀어쓰기. ("불요" → "필요 없음")
- `MVP`처럼 흔한 약어도 첫 등장 1회는 풀어쓴다. (`MVP(최소 기능 제품)`)

### 8. 줄글 단락 (글머리기호로 분해)

- 자동 grep으로 안 잡힘 → **본문을 읽고** 판단:
  - 콜론 뒤 장문, `~한다`로 끝나는 풀어쓴 단락이 있으면 한 문장 한 메시지로 `-` 글머리기호 분해
  - 결론(BLUF) 자리에 요약표가 동반되는가? 글로만 결론 쓰면 안 됨

## 출력 형식

검사 결과를 **표 하나**로 요약한 뒤, 위반 항목별 수정 제안을 붙인다.

| 검사 항목 | 매칭 줄 | 판정 | 수정 제안 |
|---|---|---|---|
| 1. 막연한 형용사 | L12 "풍부하다" | 위반 | 수치로 교체 → ... |
| 2. 출처 없는 수치 | L20 "80%" | 위반 | 출처·라벨 추가 → ... |
| ... | | 통과 | — |

- 위반이 0건이면: "전체 통과 — 저장 가능" 한 줄로 끝낸다.
- `--fix` 인자가 주어지면: 제안을 본문에 직접 반영(Edit)한 뒤 다시 검사한다.

## 적용 우선순위 (충돌 시)

1. 사용자의 직접 지시 (그 순간)
2. 프로젝트 `WRITING_RULES.md`의 프로젝트 특화 규칙 (있으면 읽어서 반영)
3. 7대 원칙 및 형식 디폴트
4. 일반 테크니컬 라이팅 관습

> 참고: 이 스킬은 farming 프로젝트의 `CLAUDE.md` 6·7번과 `WRITING_RULES.md`, 메모리 `writing-no-prose-bullets.md`를 범용화한 것이다. 프로젝트에 `WRITING_RULES.md`가 있으면 그 파일의 `프로젝트 특화 규칙`을 먼저 읽어 추가 검사 항목으로 반영한다.
